# RAG家庭教師 設計メモ

目的: 自分の提出コードをもとに、最小修正でACするコードと、ずれの解説、
次に解く問題を提示する自分専用の家庭教師。

## 流れ

1. LLM（1回目）: 問題文と提出コードから最小修正コード、ずれの一文、
   ミスの種類、教訓、正しい考え方の一文を出す（過去の記録は見せない）
2. 修正コードをサンプル入力で実行して確認（通らなければ最大2回やり直し）
3. 差分の大きさで「書き方のミス」「考え方のミス」に分岐（プログラムで判定）
4. 記録帳（SQLite の mistake_logs）に保存し、同じミスの回数をSQLで集計
5. 公式解説ストアを検索（RAGはここだけ）
   - 検索1: 本問の解説本文 → 同じ解き方の過去問
   - 検索2: 正しい考え方の一文 → 同じ落とし穴の過去問
6. AC済みは「参考」、未ACは「次に解く問題」に振り分け（難易度±400）
7. LLM（2回目）: 解説を生成

## 方針

- ベクトル検索を使うのは公式解説ストアだけ。記録帳は量が少なく構造化されているのでSQL
- 解説の本文はGeminiに渡さず、問題IDとタイトルのみ渡すことを検討中（AtCoderのnoai指定のため）
- 機械学習は今は入れない

## 段階1で分かったこと

- ミスの言葉より、解説の言葉で検索したほうが当たる（二分探索で4/10→7/10）
- 手法名が解説に出てくる場合は、平たい言い換えより手法名のほうが当たる（いもす法）
- 次はハイブリッド検索（キーワード＋ベクトル、RRF）を試す予定。その前に評価用データを作る
